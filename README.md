# 제조 통합 플랫폼

업종에 상관없이 쓰는 제조 통합 플랫폼입니다. 기준정보(MDM)를 뿌리로 두고 생산(MES), 품질(QMS·SPC), 설계 변경(PLM)을 같은 데이터 위에 차례로 올립니다.

지금은 첫 단계인 **기준정보** 모듈이 동작합니다.

## 지금 되는 것

| 화면 | 하는 일 |
|---|---|
| 현황 | 등록 현황과 기준정보 점검. 생산·품질 기록을 시작하기 전에 고쳐야 할 데이터를 찾아 해당 화면으로 연결 |
| 품목 | 완제품·반제품·원자재·부자재·소모품 등록. 조달 구분, 표준단가, LOT 관리, 사용자 정의 속성 |
| BOM | 여러 단계 정전개, 자재 소요량 합계, 재료비 계산, 사용처(역전개), 순환 방지, 다른 품목에서 복사 |
| 공정 · 라우팅 | 품목별 공정 순서와 작업장·설비·표준시간. 병목 공정과 시간당 생산량 계산, 외주 공정 |
| 설비 · 작업장 · 거래처 | 기본 등록과 조회, CSV 내보내기 |
| 공통코드 | 단위, 품목 그룹, 공정·설비 유형, 불량 유형, 비가동 사유를 직접 정의 |
| 사용자 정의 속성 | 품목·설비·공정에 업종별 관리 항목 추가 (예: 캐비티 수, 도면 번호, MSL 등급) |
| 데이터 관리 | 업종별 예시 데이터(사출 성형, 기계 가공, 전자 조립) 전환, 백업 내보내기·불러오기 |

## 업종에 묶이지 않는 방법

- 공정 종류, 불량 유형, 단위 같은 분류를 코드에 넣지 않고 **공통코드**로 둡니다.
- 업종마다 다른 관리 항목은 **사용자 정의 속성**으로 추가합니다. 등록하면 입력 화면과 CSV에 바로 나타납니다.
- 예시 데이터 세 가지가 같은 화면에서 그대로 동작하는 것을 테스트로 확인합니다.

부품을 가공·조립하는 업종을 기준으로 만들었습니다. 식품·화학처럼 배합비와 배치 단위로 생산하는 업종은 아직 다루지 않습니다.

## 실행

Node.js 22 이상이 필요합니다.

```bash
npm install
npm run dev        # 개발 서버
npm test           # 핵심 로직 테스트
npm run build      # 타입 검사 후 dist/ 에 빌드
```

데이터는 브라우저(localStorage)에만 저장됩니다. 서버가 없어서 정적 호스팅에 그대로 올릴 수 있습니다.

## 구조

```
src/
  core/        화면과 무관한 핵심 로직. 전부 순수 함수이고 테스트가 붙어 있음
    types.ts       도메인 모델
    validate.ts    저장 규칙 (필수, 중복, BOM 순환, 작업장-설비 일치 등)
    commands.ts    저장, 삭제 보호와 연쇄 삭제, 복사, 백업 읽기
    bom.ts         정전개, 소요량 합계, 역전개, 재료비
    routing.ts     표준시간 합계, 병목, 시간당 생산량
    health.ts      기준정보 점검 규칙
    store.ts       상태 보관과 브라우저 저장. 서버로 바꿀 때 이 파일만 교체
    templates/     업종별 예시 데이터
  ui/          공통 화면 부품 (표, 입력, 대화창, 공통 등록 화면)
  pages/       화면별 구성
  app/         틀과 화면 전환
```

규칙은 화면이 아니라 `core`에 있습니다. 예시 데이터와 백업 불러오기도 같은 검증을 거치므로, 화면을 거치지 않고는 들어갈 수 없는 데이터가 없습니다.

## 다음 단계

1. **MES**: 작업지시, 공정별 생산 실적, 불량·비가동 기록
2. **QMS · SPC**: 검사 기준과 기록, 관리도, 공정 능력(Cp, Cpk)
3. **PLM**: 설계 변경 요청과 승인, BOM 개정 이력
4. 서버와 데이터베이스 연결, 사용자·권한

## 배포

`main` 브랜치에 올라가면 GitHub Actions가 테스트와 빌드를 거쳐 GitHub Pages에 배포합니다. 저장소 설정의 Pages에서 Source를 "GitHub Actions"로 한 번 바꿔야 합니다.
